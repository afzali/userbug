# userbug

ابزاری که اپِ وب شما را مثل یک کاربرِ واقعی می‌آزماید، و خروجی‌اش **تستِ
پلی‌رایت** است — نه فایلی که فقط این ابزار بفهمد.

---

## ایده در یک جمله

هوش مصنوعی **یک بار** پول می‌گیرد تا مسیرها را کشف کند و تست بنویسد؛ از آن
به بعد تست‌ها مثل هر تستِ دیگری اجرا می‌شوند — رایگان، سریع، در CI.

```
۱. تألیف    کاوش + گشت + شناخت  →  tests/userbug/*.spec.js      [AI]
۲. اجرا     userbug test <هدف>   →  «۲۴ پاس، ۲ فیل»              رایگان
۳. تشخیص    trace + لاگ + diff   →  «تغییرِ X مسیرِ Y را شکست»    [AI، فقط وقتی شکست]
```

**شروع از صفر: [docs/شروع.md](docs/شروع.md)**

## چه چیزی را پلی‌رایت نمی‌دهد

اگر فقط تست می‌خواهید، پلی‌رایت کافی است. userbug پنج چیز اضافه می‌کند:

| | |
|---|---|
| **همبستگیِ لاگ** | `ub.step()` مرزِ زمانیِ هر قدم را می‌گذارد، پس معلوم است کدام خطِ لاگِ سرور مالِ کدام کنشِ کاربر است |
| **شناختِ اپ** | هر بند با `by:` می‌گوید از کجا آمده — گشت، خزش، یا حرفِ خودتان |
| **چکِ قراردادی** | «این دکمه همیشه اینجا بود، حالا نیست» — نامتغیری که یاد گرفته، نه تستی که نوشته‌اید |
| **یافته و تریاژ** | شکست‌ها به فهرستِ باگِ بدونِ تکرار تبدیل می‌شوند |
| **کشفِ مسیر** | مسیرهایی که خودتان به آن‌ها فکر نکرده بودید |

## نصب

یک بار، برای خودِ userbug:

```bash
npm install
npx playwright install chromium
npm link
```

و برای هر پروژه‌ای که می‌آزمایید — **از داخلِ پوشهٔ خودش**:

```bash
cd <پروژهٔ شما>
userbug setup --base-url http://localhost:5173
```

همین. پوشه، دو کانفیگ، `.npmrc`، وابستگی‌ها و مرورگر را خودش می‌سازد و
نصب می‌کند — با نسخهٔ پلی‌رایتی که خودش با آن ساخته شده، تا دو نسخه در کار
نباشد.

بعد از آن، داخلِ پروژه حتی نامِ هدف هم لازم نیست:

```bash
userbug tour
userbug expect
npx playwright test
```

> **کد نمی‌نویسید.** فایل‌های تست را userbug می‌سازد. اگر جایی خطی مثل
> `import { test } from 'userbug/test'` دیدید، آن **داخلِ فایلِ تولیدشده**
> است، نه چیزی که باید تایپ کنید.

راهِ گام‌به‌گام از صفر: **[docs/شروع.md](docs/شروع.md)**

## تعریفِ یک پروژه

```bash
userbug init <هدف>
```

یک `targets/<هدف>.config.js` می‌سازد:

```js
export default {
  baseURL: 'http://localhost:5173',
  apiURL: 'http://127.0.0.1:8081',
  environment: 'local',            // دروازهٔ ایمنی — نبودش یعنی production

  logs: [
    { type: 'file', name: 'back', path: '${APP_ROOT}/logs/error.log' },
  ],

  source: { root: '${APP_ROOT}' },  // فقط‌خواندنی، با اجازهٔ صریح
};
```

`${VAR}` از `.env` خوانده می‌شود و `.env` در گیت نیست — پس این فایل قابلِ
حمل می‌ماند و تفاوتِ ماشین‌ها یک‌جا جمع می‌شود.

## گشت — جایی که شما و ابزار با هم کار می‌کنید

```bash
userbug tour <هدف>
```

مرورگر باز می‌شود، **شما کار می‌کنید**، و ابزار ضبط می‌کند: کلیک و پر کردن
با توصیفِ معنایی (نقش و برچسب، نه سلکتور) تا تغییرِ ساختارِ HTML نشکندشان.
ترمینال کانالِ حرف زدنِ شماست:

```
گشت> <متن>            توضیحِ صفحهٔ فعلی
گشت> v <نام>          نامِ لایهٔ فعلی (مودال/کشویی)
گشت> v <نام> | <متن>  نام و توضیح با هم
گشت> n <متن>          یادداشت یا ایراد
گشت> p                صفحه را بی‌توضیح ثبت کن
گشت> r                ضبط را روشن/خاموش کن
گشت> q                پایان
```

و هم‌زمان جریانِ زنده چاپ می‌شود: `●` قدم، `⚠` یافته، `→` ناوبری.

خروجیِ گشت یک `.spec.js` در ریپوی پروژهٔ شماست، و **عنوانِ هر بلوک از
توضیحی که خودتان تایپ کرده‌اید** ساخته می‌شود:

```js
await ub.step('/contents — کتابخانهٔ من', async () => {
  await page.getByRole('button', { name: 'افزودن کتاب', exact: true }).click();
  await page.getByLabel('فایل', { exact: true }).setInputFiles(await ub.fixture('نمونه.pdf'));
});
```

یعنی حرفِ شما در گزارشِ تست دیده می‌شود — و همان عنوان بعداً **لنگرِ درجِ
ادعا**ست.

## خزشِ خودکار — و حرف زدن وسطش

```bash
userbug map <هدف> --headed
```

`--headed` یعنی صفحه را می‌بینید. و حینِ خزش در همان ترمینال:

```
n <متن>   یادداشت/ایراد دربارهٔ همین لحظه — یافتهٔ واقعی می‌شود
w         الان کجاست؟ (مسیر · حالت · صف · یافته)
q         بس است — تمیز بایست و آنچه پیدا شده را نگه دار
```

`q` قطعِ فوری نیست: خزش ممکن است وسطِ رندر یا نوشتنِ قرارداد باشد و قطعِ
همان‌جا نقشه‌ای نیمه‌نوشته می‌گذارد. پرچم می‌نشیند و حلقه در نخستین مرزِ
امن بیرون می‌آید.

## کارهای دیگر

```bash
userbug impact <هدف>       «کد عوض شد — کدام تست‌ها باید دوباره فکر شوند؟»
userbug map <هدف>          خزشِ خودکار — ارزان، بی کمک
userbug learn <هدف>        هضمِ سورس → شناخت
userbug knowledge <هدف>    پروندهٔ شناخت
userbug capabilities <هدف> «این اپ چه دارد؟»
userbug coverage <هدف>     «چه چیزی در سورس هست و صدایش نزده‌ایم»
userbug expect <هدف> --list          عنصرهای واقعی، رایگان
userbug expect <هدف> --from <فایل>   پیشنهادِ ادعا       [AI]
userbug report <هدف>       گزارش
```

### `impact` — پاسخِ «فلان تغییر را دادی، چه شد؟»

سه چیز را به هم وصل می‌کند: گیت می‌گوید کدام فایل‌ها عوض شدند، پرونده
می‌گوید هر فایل کدام صفحه را می‌سازد، و تست‌ها می‌گویند کدام صفحه را لمس
می‌کنند.

مهم‌ترین خروجی‌اش چیزی است که **پیدا نشد**: فایلی که به هیچ صفحه‌ای نگاشت
نشود جدا گزارش می‌شود، نه به‌عنوان زیرنویس — چون «چیزی لازم نیست» دربارهٔ
فایلی که به همه‌جا اثر دارد، دروغِ آرام است.

و تست را بازنویسی نمی‌کند. وسوسه‌اش هست، ولی آن یعنی مدل می‌تواند انتظارِ
درست را با **باگِ امروز** جایگزین کند: تست سبز می‌شود و باگ می‌ماند.

## فایل‌های نمونه

تستِ آپلود به فایلِ واقعی نیاز دارد:

```bash
userbug fixtures <هدف> --add ./نمونه.pdf --note "برای آزمونِ آپلودِ تکراری"
userbug fixtures <هدف>                    فهرست
```

فعلِ `upload` **فقط** از این پوشه می‌خوانَد، نه از هر جای دیسک. این
محدودیت عمدی است: مسیرِ آزاد یعنی سناریویی که می‌تواند هر فایلی از ماشین
شما را بفرستد.

## فارسی در ترمینال

دو چیز جداست و فقط یکی‌اش کارِ ماست.

**حسابِ ستون‌ها — حل شده.** `String.length` واحدهای UTF-16 را می‌شمارد و
در فارسی این با آنچه چشم می‌بیند یکی نیست: `'می‌کند'` شش واحد است و پنج
ستون، چون نیم‌فاصله جا نمی‌گیرد. `src/terminal.js` عرضِ نمایشی را حساب
می‌کند — اعراب، نشانه‌های جهت و کدِ رنگ را نمی‌شمارد و نویسهٔ پهن را دو.

**ترتیبِ دیداری — کارِ ترمینالِ شماست.** `cmd.exe` فارسی را جدا و وارونه
نشان می‌دهد حتی با `chcp 65001`. **Windows Terminal** درست نشان می‌دهد؛
اگر خروجی به‌هم‌ریخته دیدید، اول ترمینال را عوض کنید.

ورودی مشکلی ندارد: `readline` فارسی را درست می‌گیرد، و در گشت می‌توانید
توضیح و نام و یادداشت را فارسی بنویسید.

## ادعا: نرم و سخت

پیشنهادِ مدل **نرم** درج می‌شود و تأییدِ شما سختش می‌کند:

```js
await expect.soft(locator, 'چرا').toBeVisible();  // یافته ثبت، اجرا ادامه
await expect(locator).toBeVisible();              // با --hard: همان‌جا می‌شکند
```

حرفِ نیازمودهٔ مدل نباید بتواند بقیهٔ تست را از اجرا بیندازد.

## کجا چه می‌نشیند

```
<پروژهٔ شما>/tests/userbug/
  *.spec.js       تست‌ها          ← در گیتِ همان پروژه
  knowledge/      شناختِ اپ
  triage/         قضاوتِ شما
  findings.md     فهرستِ باگ
  .local/         راز، نشستِ مرورگر، نقشه، اجراها — ignore

userbug/targets/<هدف>.config.js   آدرس، لاگ، سورس
```

تست دارایی اپ است: با کد بازبینی می‌شود، در CI همان پروژه می‌رود، و در
PRی می‌شکند که شکستش.

## وضعیت

`userbug author` هنوز نوشته نشده: فایلِ اولیهٔ `.spec.js` را دستی بنویسید،
بعد `userbug expect` رویش کار می‌کند.

## اجرا

```bash
npx playwright test          # تست‌ها
npx playwright test --ui     # تماشا و قدم‌به‌قدم
npm test                     # خودآزماهای خودِ userbug
```
