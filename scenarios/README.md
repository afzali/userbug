# فرمت سناریو

سناریوها فایل YAML در `scenarios/<هدف>/` هستند. هر فایل یک تست می‌شود.

```yaml
name: ایمیل با حرف بزرگ، حساب دوم می‌سازد
persona: novice          # اختیاری
device: Pixel 7          # اختیاری — بازنویسی دستگاهِ هدف
status: approved         # یا draft
steps: [...]
```

`status: draft` یعنی سناریو هنوز بازبینی انسانی نشده — اجرا می‌شود ولی در
گزارش علامت می‌خورد و رگرسیون شمرده نمی‌شود. سناریویی که در فاز ۲ مدل
می‌نویسد همیشه پیش‌نویس متولد می‌شود، چون رفتار **فعلی** اپ را ثبت می‌کند و
اگر امروز باگی باشد، آن را به‌عنوان «انتظارِ درست» رسمی می‌کند.

## دو نوع سنجش

| فعل | اگر نخورد |
|---|---|
| `expect` | سناریو می‌شکند — ادامه‌اش بی‌معناست |
| `assert` | **یافته ثبت می‌شود** و سناریو ادامه می‌دهد |

این تفاوت هستهٔ کار است. بیشتر باگ‌ها جایی‌اند که اپ به کارش ادامه می‌دهد و
فقط چیزِ غلطی انجام می‌دهد. اگر همه‌چیز `expect` بود، اولین یافته بقیهٔ مسیر
را قطع می‌کرد.

```yaml
- assert: { hidden: { role: heading, name: "کد بازیابی شما" } }
  finding: "ایمیل «{{identity.email | upperFirst}}» حساب جداگانه ساخت"
  detail: "کاربر حساب خالی می‌بیند و فکر می‌کند داده‌هایش پریده."
```

| `forEach` | حلقه روی مجموعه‌ای از مقدارها |

## توصیف هدف

رشتهٔ ساده نردبان `testid ← role ← label ← text` را از بالا می‌رود:

```yaml
- click: "ورود / ثبت‌نام"
```

یا دقیق:

```yaml
- click: { role: menuitem, name: "خروج", exact: true }
- click: { role: button, name: "{{identity.local}}", exact: false, nth: 0 }
- fill:  { label: "ایمیل" }
  value: "{{identity.email}}"
```

`exact: true` پیش‌فرض است. یک بار `getByRole('menuitem', {name: 'خروج'})` هم
به «خروج» خورد و هم به «خروجی گرفتن از اطلاعات» — از آن به بعد پیش‌فرض دقیق شد.

## متغیرها

```
{{identity.email}}      {{identity.password}}     {{identity.local}}
{{nasty.zwnj}}          {{nasty.persianDigits}}   {{vars.<نام>}}
```

فیلترها: `upper` · `lower` · `trim` · `upperFirst` · `localPart`

## پرسونا

`persona: novice` یا `pro` در سرِ فایل؛ `--persona` در خط فرمان بر آن می‌چربد.

| | `novice` | `pro` |
|---|---|---|
| تایپ | حرف‌به‌حرف با ۶۰ms فاصله | `fill` یکجا |
| پیش از کلیک | ۳۵۰ms مکث | بدون مکث |
| پس از ناوبری | ۵۰۰ms | بدون مکث |

این تزئین نیست. یافتهٔ ۵ نپی از همین‌جا آمد: بررسی یکتاییِ عنوان ۵۰۰
میلی‌ثانیه تأخیر دارد، پس `pro` از کنارش رد می‌شود و `novice` نمی‌شود. و
`fill` هیچ رخداد کیبوردی تولید نمی‌کند، پس هر منطقی که به تایپِ تدریجی وابسته
است — debounce، اعتبارسنجی زنده — با `pro` اصلاً اجرا نمی‌شود.

## گروه‌بندی

`as:` سرِ گروه است، نه فقط برچسب. قدم‌های بعدی تا `as:` بعدی زیر همان گروه
می‌آیند و یک قدم در گزارش می‌شوند — با یک عکس و یک بازهٔ زمانی برای لاگ سرور.
بدون آن، هر فعل یک ردیف در گزارش می‌شد و خط زمانی از خواندن می‌افتاد.

## `do:` — قدم به زبان طبیعی

```yaml
- do: دکمهٔ ورود یا ثبت‌نام را بزن
- do: ایمیل حساب را وارد کن
  value: "{{identity.email}}"
```

**نکتهٔ اصلی اقتصاد آن است، نه کارکردش.** هر نیت که یک بار حل شد در
`_learned/<سناریو>.json` می‌نشیند و دفعه‌های بعد **بدون هیچ تماسی با مدل**
اجرا می‌شود. سناریویی که کشش کامل باشد، بدون کلید هم اجرا می‌شود.

مدل فقط در دو حالت صدا زده می‌شود:

- نیت تازه است و کش ندارد
- کش دارد ولی **امضای ساختاری** عنصر عوض شده

امضا همان چیزی است که جلوی خطرناک‌ترین حالت را می‌گیرد: selector هنوز چیزی
پیدا می‌کند ولی معنایش عوض شده. آن‌وقت تست سبز می‌شود و باگ رد می‌شود.

**کش می‌گوید «کجا»، سناریو می‌گوید «چه».** مقدارها (`value`) در سناریو
می‌مانند تا هر اجرا هویت خودش را داشته باشد — اگر کش می‌شدند، ایمیلِ اجرای
قبلی در فایل باقی می‌ماند.

پوشهٔ `_learned/` در گیت می‌ماند و در `.gitignore` نیست: مسیرِ یادگرفته‌شده
سرمایه است نه فایل موقت. اگر محلی بماند، هر نفر و هر اجرای CI دوباره از اول
پول می‌دهد.

## چه چیزی هنوز نیست

`explore:` و `goal:` — کاوش آزاد با منشور. فاز ۲ ادامه دارد.
